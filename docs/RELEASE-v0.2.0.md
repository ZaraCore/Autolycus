# v0.2.0 发布说明

本版本整合 Ubuntu cron 调度与飞书报告展示优化。发布和 CI 通过不等于现场验收完成；Ubuntu 现有容器不会因上传代码自动切换版本。

## 主要变化

- Ubuntu 用容器内 Supercronic 按 `config.toml` 生成的北京时间任务触发巡检，取消 Python 每10秒检查计划。Windows 任务计划保持原样。
- 继续使用计划防重、文件锁、数据库、单次超时和同计划有限重试。启动/恢复时等待下一触发点，不补跑已经错过的任务。
- 飞书保持静态 Markdown 卡片；渠道、分组改为逐行显示，模型按分组显示标题，每行包含模型、分组、成功次数、P50、P95。
- 成功率、延迟及不可用提示支持可配置的红/橙色显示；颜色是展示阈值，不是模型 SLA 或新告警规则。
- 部署模板预置 OpenAI、OpenAI 官key 各5个，Banana、Gemini官key 各7个，共24个分组模型目标，默认仍关闭。

## 旧部署迁移

1. 保留 `.env`、`config.toml`、数据卷与数据库备份；继续确保只有一个主动发送端。
2. 使用支持可选网络参数的升级脚本升级至 `v0.2.0`。新版 Dockerfile 增加 Go 构建阶段，首次构建会额外下载 Go 镜像及 Supercronic 模块；普通服务器无需代理，特殊环境按需传参。
3. 现有 `[schedule]` 直接用于生成 cron，明确保留时间表。模板是北京时间工作日09:00—18:00整点、周末09:00/12:00/18:00，不处理法定节假日。
4. 模型模板不会覆盖本地名单。需要 Banana 等新目标时，人工合并模板中的 `[[model_performance.targets]]`，避免重复；保留本地 `enabled` 设置。只升级代码不会自动增加这些模型。
5. `[highlight]` 可省略，程序使用默认颜色阈值；关闭颜色可配置 `enabled=false`。详见 [配置手册](CONFIGURATION.md)。

升级脚本更新程序镜像，不自动替换宿主机脚本或 Compose；本版本运行入口和 cron 二进制均在镜像内，沿用原数据卷和健康检查命令，无需在宿主机另装 cron。此前未更新升级脚本的部署，应先获取新版脚本。

已经成功发送的定时报告按数据库缓存原正文，重试不会按新格式重新生成；检查新格式应选新的计划或普通预览，不要为看样式随意强制重发。

## 验证与现场检查

发布前运行 Python 测试、配置示例检查和 Linux Docker CI。CI 在禁网、非 root、只读根目录环境验证真实 cron 触发、启动、健康、锁和退出；不使用真实站点凭据。

Ubuntu 现场仍需确认：镜像版本、cron 时间表、下一个计划的实际送达、逐行与颜色显示、模型名单、暂停恢复和回退。`healthy` 只证明 cron 进程存活。详见 [cron 调度说明](CRON.md)。
