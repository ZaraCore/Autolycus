# v0.2.2 发布说明

修复 v0.2.1 在四个重点模型分组都有数据时，卡片表格数量过多导致飞书拒绝发送的问题（11246 / 子错误码11310）。

- 四个模型分组合并为一张表，列为分组、模型、成功次数、P50、P95；保留分组顺序、名称加粗和延迟颜色。
- 渠道和分组成功率各一张表，整份报告最多三张表。
- 发送前检查当前 Markdown 组件的表格数，超过四张直接报明确错误，不继续提交无效卡片。
- 飞书业务失败时显示数字错误码及可识别的子错误码，表格超限不再误提示为安全设置问题；不输出上游完整响应或密钥。

飞书 [官方富文本说明](https://open.larkoffice.com/document/feishu-cards/feishu-card-cardkit/components/markdown)规定单个组件最多四张 Markdown 表格；超过五行的数据会分页展示，不代表丢失数据。模型表变宽后，实际移动端和桌面端显示需现场验收。

本版本无需修改 `.env` 或 `config.toml`，不改变 cron、采集范围、防重和重试行为。升级目标为 `v0.2.2`，Ubuntu 运行中的容器不会自动更新。

旧失败计划的数据库缓存仍保留旧版多表正文，不会因升级自动重排；该缓存可能被新的本地表格检查拒绝。验收时应使用新计划或普通预览。此前已耗尽三次尝试的计划也不会自动补发；不要直接强制重发旧缓存。

测试覆盖四个模型组全部有数据的完整三表报告、零成功和查询失败、表格数量边界，以及错误码提示和敏感响应不外泄。Linux CI 继续检查镜像构建与 cron 集成。通过测试不代替飞书真实投递验收。
